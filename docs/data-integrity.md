# 档案与备份规则

## 导入与关联

- 数据中心先解析并展示有效 / 跳过数量、目标图层和导入方式，确认后才修改项目；取消不会改动当前档案。
- “追加”保留已有要素，重复遗址 ID / 已匹配档案会被拒绝；“替换图层”更新该图层，不清空笔记。混合来源追加后，图层级年代与统一 SHA-256 不再代表全部数据，需重新核验；各次导入来源仍保留。
- 优先使用稳定且唯一的原始遗址 ID。内部关联不包含坐标，也不依赖行号。无 ID 数据只对唯一的名称 / 时期 / 类型 / 地点组合做匹配；无法确认时保留旧记录，不把旧模型猜测性地关联到新记录。
- 导出 GeoJSON 中的 `source_id` 和 `legacy_identity` 用于安全保留原始 ID 与旧版内部 ID 的区别，请勿随意修改。
- 暂时从名录移除的遗址笔记与模型仍保存在项目中，并包含在完整备份里；它们不会出现在当前名录的选择器中。

## 旧版浏览器档案

既有 `heritage-project-v2` 首次读取时增加项目独立的档案标识。只对这份既有项目查找旧版坐标键；新建 / 恢复的项目不会连接到其他项目的模型。

旧版模型和采集清单仅在遗址 ID 匹配且只有一组候选坐标记录时迁移。原键不删除。多组记录不能可靠判断时，显示错误并保留全部记录；完整备份包含这些未确定关联的旧档案。读取失败时不会用空采集清单覆盖原档案。项目读取失败时暂停自动保存，明确显示临时演示数据。

## 完整备份

`.heritage` 是带版本、长度字段和 SHA-256 的二进制容器。清单包含项目数据、模型目录、照片清单和未关联旧记录，后接模型原始字节。元数据及各段模型字节均校验；相同模型字节只存一份，关联记录分别保留。

- 每个模型：大于 0 且不超过 120 MiB
- 元数据：不超过 80 MiB
- 完整文件：不超过 512 MiB
- 照片登记：仅名称、大小、修改时间和检查项，**不包含照片原件**，原照片须单独保存

恢复会先验证整个文件，随后在一个 IndexedDB 事务中写入项目和全部档案。配额不足 / 文件损坏时不会报告恢复成功。每次恢复使用新的独立档案标识；旧项目的模型键不被改写。旧版 JSON 可以恢复图层和笔记，但本来未包含的模型与照片无法由 JSON 找回。

## 模型有效状态

格式和文件头检查仅是预检。查看器实际解析成功、点数有效且全部点坐标有限 / 范围有效后，模型才可写入有效档案。失败候选不替换已存模型；切换遗址后的过期回调不能写入其他遗址。已存模型和恢复的模型再次打开时仍需加载验证。高斯模型不是测绘精度、地理配准或结构安全认证。

## 验证

运行 `npm run build && npm test`。单元回归覆盖 ID 重排 / 坐标更新、旧版迁移冲突、孤立笔记、追加上限、跨项目隔离、字节 / 元数据损坏、配额失败、采集读失败、过期回调和有效模型提交。

浏览器验收应补充：桌面 / 手机数据中心布局；预览取消；追加重复 ID；替换后笔记保留；完整备份恢复；有效模型后导入损坏模型；解析时切换遗址；查看器 WebGL 错误与重试。构建与单元测试不替代这些实际浏览器检查。
