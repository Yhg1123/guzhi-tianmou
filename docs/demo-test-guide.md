# 古址天眸：虚构演示数据与主流程测试指南

## 数据声明

本包全部内容仅用于软件测试。点位名称、经纬度、时期、地形值、水系、交通线、边界和影响区均为虚构；不对应真实遗址、实测记录、法定保护范围或灾害评估。数值不能用于考古研究结论。

- `synthetic-calibration.splat`：从程序 `createSampleSplat()` 生成的合成校准样例中等距抽取 256 个点，8,192 字节；不是实测建筑、照片重建或尺度标定模型。抽稀后主要用于导入测试，不代表展示质量。
- `FAKE-NOT-A-PHOTO-01.png` 至 `03.png`：3 张 16 × 16 彩色像素测试图，仅用于文件选择和清单登记；不是现场照片，不能用于摄影测量或模型训练。
- `fake-photo-metadata.json`：上述文件的名字、大小和固定修改时间。全部采集检查项初始为否；不代表已经取得真实拍摄授权或完成质量检查。
- `.heritage` 备份包含模型字节及照片清单元数据，不包含照片原件。测试 PNG 作为独立文件提供。

## 文件用途

所有数据文件位于 `tests/fixtures/heritage-demo/`；下载压缩包内也提供相同文件。

| 文件 | 用途与预期结果 |
| --- | --- |
| `demo-full.heritage` | 快速恢复：3 个虚构点位、5 类图层、甲号点的测试笔记、合成模型和 3 条图片元数据；恢复后模型仍须由实际查看器重新验证 |
| `sites-initial.geojson` | 初始甲、乙、丙 3 点；稳定 ID 为 `DEMO-ONLY-A/B/C` |
| `sites-addition.geojson` | 丁号点 `DEMO-ONLY-D`；追加后共 4 点，再次追加应拒绝重复 ID |
| `sites-reordered-corrected.geojson` | 顺序调整为丁、丙、甲、乙；甲号点更正为经度 110.002、纬度 35.003，ID 不变 |
| `sites-duplicate-ids.geojson` | 同一文件内两个点使用同一个 ID；应拒绝解析 |
| `sites-invalid-coordinates.geojson` | 经度 181 / 纬度 91，2 点均越界；应提示无有效点位 |
| `sites-mixed-invalid.geojson` | 1 个有效乙号点 + 2 个越界点；预览应显示有效 1、跳过 2；不要误确认替换现有项目 |
| `waterways.geojson` / `routes.geojson` | 各 1 条虚构线；所属时期为“虚构时期甲” |
| `boundaries.geojson` / `hazards.geojson` | 各 1 个虚构多边形；甲号点在边界样本内、丙号点在影响区样本内 |
| `sources.json` | 各图层建议使用的演示时态、出处和文件 SHA-256；供核对，不是独立上传入口 |
| `manifest.json` | 包内生成数据文件的大小、SHA-256 与明确的合成说明 |

## 可重复执行的脚本测试

在项目根目录执行；需要已安装项目依赖。建议 Node.js 20+，本次使用 Node.js 24.19.0（测试使用内置 `File`、`Blob` 和 Web Crypto）。未新增依赖。

```sh
# 仅运行本次新增的主流程集成测试
node --test tests/heritage-flow.test.mjs

# 运行完整测试集、生产构建与 Sites 工作者测试
npm run build
npm test
npm run test:sites

# 重新生成测试包：建议输出到临时目录，避免覆盖随仓库提供的版本
node tests/fixtures/heritage-demo/generate-fixtures.mjs /tmp/heritage-demo
```

新增测试调用真实的 GeoJSON、项目导入、档案读写、备份恢复、操作锁和模型几何检查函数；存储使用内存适配器，模型中心来自标准 32 字节记录的测试专用解码。覆盖以下行为：

1. 导入 5 类图层，保留缺失地形值；区分同期水系/交通距离与现状影响区。
2. 保存甲号点的虚构笔记、合成模型、图片清单；追加丁号点并拒绝重复追加。
3. 替换重排和坐标修正后的点位，核对稳定 ID、笔记和模型关联。
4. 完整二进制备份恢复：核对所有图层、模型逐字节内容、文件元数据及采集清单；恢复后的模型状态必须为待验证。
5. 篡改备份模型字节、元数据或截断文件均应失败，已有项目不应写入或替换。
6. 模型非有限坐标被拒绝；失效导入回调不得写入。取消慢速恢复须等待终止结果后释放操作锁。
7. 检查合成模型生成的可重复性、下载文件校验值以及 PNG 与照片清单的匹配。

这些是 Node 函数级主流程集成测试，不是已渲染浏览器 UI 的端到端测试，也未覆盖真实 IndexedDB 事务、真实 GaussianSplats3D 解析器、WebGL 渲染、真实照片训练服务或视频录制。仓库其他测试的结论须分别按其执行记录核对。

## 浏览器可用时的人工验收顺序

先保留当前工作的完整备份，建议在专门的测试浏览器配置中操作。以下是待执行清单，不是已完成记录。

1. 数据中心 → 恢复项目 → 选择 `demo-full.heritage` → 查看确认提示 → 校验并恢复。核对 3 个点、5 个图层，以及“演示”标识。
2. 遗址档案选择“【虚构】甲号测试点”；在保护相关页面核对测试笔记。在三维档案等待实际模型加载，确认成功后再判断能否保存和重新打开。可再次选择 `synthetic-calibration.splat` 测试导入；失败时保留错误提示，不能记为通过。
3. 三维档案 → 重建准备 → 选择照片，选中 3 张 `FAKE-NOT-A-PHOTO-*.png`。应登记 3 项、明确未上传或开始训练；导出任务清单核对名称。切换遗址后应与原遗址清单隔离。
4. 数据中心将遗址图层设为“追加”，选择 `sites-addition.geojson`。先取消一次，点数应仍为 3；再确认追加，点数应为 4；重复追加应报错且保持 4 点。
5. 切换为“替换图层”，导入 `sites-reordered-corrected.geojson`。核对甲号点坐标 110.002 / 35.003，原笔记、模型及采集清单仍关联甲号点。
6. 分别选择重复 ID、全越界、混合无效点文件，核对错误或跳过数量；不要确认混合文件的替换操作。
7. 导出完整 `.heritage`，重新打开页面并恢复此备份。核对点数、笔记、模型、清单及恢复后重新加载验证；浏览器下载完成本身不代表数据已经核对。
8. 用备份副本测试损坏文件拒绝；恢复过程中离开数据中心时，核对取消与编辑锁行为。小样本可能瞬间完成，不能由此证明慢速竞态已覆盖。
9. 切到窄屏，检查文件预览、错误提示、确认/取消按钮可见且可操作；检查控制台错误与 WebGL 兼容性。

若从分层文件开始而不使用完整备份，先替换 `sites-initial.geojson`，再分别导入其余 4 个图层；按 `sources.json` 补充演示时态和出处。水系、交通线应设置为“历史重建”，时期填写“虚构时期甲”；改为“现状数据”后不应把它们算作同期历史因素。
